# MSX Music Alchemy — 使用方法

## 1. 起動と保存

Windows x64版ZIPを展開し、`MSXMusicAlchemy.exe` を起動します。ブラウザーで
`http://127.0.0.1:7913` が開きます。データはPC内に保存されます。
終了は起動時のサーバーウィンドウを閉じてください。
ソース版はPython 3.10以降を用意して `start.bat`。音源エンジンを再ビルドする場合は
Visual Studio C++とCMakeをインストールして `build.ps1` を実行します。

初回はデモ曲Starlight Circuitが表示されます。「新規」で空の曲を始められます。
「JSON保存」で任意の場所に楽曲を保存し、「読み込む」でそのJSONを開きます。
自動保存先はソース版が `data/autosave.json`、Windows版が
`%LOCALAPPDATA%/MSXMusicAlchemy/data/autosave.json` です。
自動保存は最後の1曲のみです。大切なバージョンはJSONで別名保存してください。

## 2. チャンネルを選ぶ

左側からトラックを選びます。各チャンネルは単音です。和音は複数のチャンネルに分けます。

| 音源 | チャンネル数 | この版の音色 |
|---|---:|---|
| PSG | 3 | 矩形波・ノイズ・ドラムキット、音量1–15 |
| OPLL | 9 | 15種のROM音色と共有カスタム音色 |
| SCC | 5 | 32サンプル波形。4/5chの波形は共有 |

`M`はミュートで、試聴・書き出し両方に反映します。`S`は選択チャンネルだけを試聴します。
ソロ状態は書き出しには反映しません。

## 3. ピアノロール

「表示小節」またはSONG OVERVIEWで小節を選びます。1画面は1小節です。
「グリッド」で入力・移動の刻み、「音長」で新規ノートの長さ、「音量」で強さを指定します。
「音域」で2オクターブの表示範囲を切り替えます。

- 空の位置をクリック: 音符を追加。
- 音符をドラッグ: 時間と音程を変更。
- 音符右端をドラッグ: 音長を変更。
- 音符を選択: 右側でMIDI音程、開始tick、音長tick、音量を数値編集。
- 右クリック、Delete、または「ノート削除」: 削除。
- Ctrl+Z / Ctrl+Y: 取り消し／やり直し。
- 「小節複製」: 選択トラックの現在小節を次の小節に複製（次小節を先に追加、空きを確保）。
  幅が狭い場合はこのボタンを隠します。

薄いノートは他のトラックの参考表示です。選択チャンネル内で音が重なる編集はできません。
既存ノートのある小節数を減らすこともできません。先にノートを移動・削除してください。

## 4. ステップ入力

「ステップ入力」を選び、カーソルのtick位置を指定します。96 ticksが四分音符、
384 ticksが1小節です。音名ボタンを押すと現在位置に音符を入力し、指定音長ぶん進みます。
同じ開始位置に既存ノートがある場合はその音程を置き換えます。
「休符」はカーソルだけを進めます。「この位置を削除」はその位置から始まる音符を削除します。

キーボード `Z S X D C V G B H N J M` でも入力できます。入力欄にフォーカスがある間は
通常の文字入力が優先されます。音程は選択した表示音域の下端Cから始まります。

## 5. 音色

OPLLは音色メニューでROM音色を選びます。Customは8バイトの16進数で入力します。
例: `21 21 1a 06 f0 f0 0f 0f`。OPLLにはユーザー音色が1組しかないため全チャンネルで共有です。

SCCはTriangle / Sine / Square / Saw、または波形をドラッグして描けます。
4/5chのどちらかを変更すると、もう一方も同じ波形になります。
PSGノイズ／ドラムキットとOPLLリズムに対応しています。PSGハードウェアエンベロープと曲途中の音色切替は未対応です。

## 6. 再生とループ

▶ / Spaceで表示中の小節から試聴、■で停止、|◀で先頭へ戻ります。
BPM、曲の小節数、50/60Hzを指定できます。LOOPと開始小節でループ区間を設定します。
試聴はローカルの音源エンジンで短い音声を順次生成するリアルタイム方式です。曲全体の音声生成を待たずに開始します。再生中の `M`（ミュート）と `S`（ソロ）は停止せず反映します（通常約0.3〜0.5秒後）。音符・音色・テンポなどの編集は再生を停止し、次回再生に反映します。途中小節からの再生では、その位置までの音源状態の準備に時間がかかる場合があります。
ループ境界を跨ぐFM音はレジスタ復元時にエンベロープが再開始するため、ノートの境界に
ループ開始を置くと自然につながります。

## 7. MMLを取り込む

「読み込む」で .mus / .mml ファイルを選ぶか、テキスト欄に貼り付けます。
UTF-8とShift-JISに対応します。読み込みは曲全体を置き換えます。戻す場合はUndo。

```text
#opll_mode 0
#tempo 120
#title { "First melody" }
1 v12 o4 l8 cdefgab>c
9 @13 v10 o2 l4 c r g r
```

MGSCのトラック1–3はPSG、4–8はSCC、9–hはOPLLです。MGSCの@0–14は
OPLLのROM音色1–15に対応します。**vを省略するとMGSC既定のv0で無音になります。**
対応構文と未対応機能は [AI_COMPOSITION.md](AI_COMPOSITION.md) に記載しています。
未対応構文は読み飛ばさずエラーにし、現在の曲を保持します。MML出力は未対応です。
編集データからのMGS出力は「ゲームへ出力 → MGSDRV (.mgs)」に対応しています。

## 8. ゲーム向け出力

「楽曲を検証」で制約を確認してから「ゲームへ出力」を開きます。
推奨は「ゲーム開発パック」。音楽JSON、レジスタ列、C/BIN、VGM、参照プレイヤー、
AI向け説明と仕様が一緒になります。ゲーム開発AIにZIPの中身とターゲット機種・
音源・マッパー・SFXチャンネルの条件を渡してください。

WAVは確認用の1回再生＋余韻です。VGMは外部プレイヤー用です。
MGSDRV (.mgs)は60 Hz・全17パート対応。FM音色・SCC波形・ループ・ミュートを反映します。
16 KiBを超える曲や50 Hzの曲は、切り捨てずエラーで停止します。
実機での再生方法と制限は [MGSDRV_EXPORT.md](MGSDRV_EXPORT.md) を参照してください。
C/BINはゲームに自動で組み込まれるものではありません。
[GAME_INTEGRATION.md](GAME_INTEGRATION.md) に従ってドライバー側を実装してください。

## 9. AI作曲

[MCP_SETUP.md](../MCP_SETUP.md) の設定をMCP対応クライアントに登録し、エディタを起動します。
AIに音楽の用途、長さ、テンポ、音源、ループの要否、変更してよいトラックを伝えます。
AIの変更は画面に自動反映されます。更新番号が違う場合は競合として止まるので、
勝手に上書きせず最新データを取得して調整してください。

このアプリにAIモデルは内蔵されていません。MCPクライアントから使用するモデルや
サービスは利用者が選びます。

## PSGドラム・減衰（v0.5.0）

PSGトラックを選び、右の「PSG発音」で「PSGドラムキット」を選びます。空トラックで始めるか、次の音程を使ってください。ステップ入力では楽器名のボタンを表示します。

| MIDI音程 | 楽器 | 自動減衰 |
|---|---|---|
| 36 (C2) | キック | 100 ms |
| 38 (D2) | スネア | 90 ms |
| 42 (F♯2) | ハイハット | 40 ms |
| 45 (A2) | タム | 140 ms |
| 49 (C♯3) | シンバル | 220 ms |

「減衰」でトラック全体を設定し、選択音符の「打楽器減衰」で個別に上書きできます。0は自動／継承です。1～2000 ms、実際の更新は50/60 Hz単位です。音符が先に終わる場合はそこで停止します。キック・タムは音程が下降し、スネアはトーンとノイズを混ぜます。

「ノイズ打楽器」ではノイズ周期1～31も編集できます。ノート固有の周期はMCP/JSONのnoisePeriodで指定します。PSGのノイズ発生器を共有するため、音符のある有効なノイズ／ドラムトラックは1本に制限しています。各トラックは単音で、同時打撃は重ねられません。

WAV・VGM・レジスタ列に対応。PSG打楽器のMGS出力は未対応としてエラーを表示します。既存の矩形波曲はそのまま利用できます。

## リアルタイム試聴（v0.7.0）

試聴は PSG・OPLL（ymfm）・SCC の既存エンジンを継続動作させ、短い音声をブラウザへ送ります。ミュート中も音源内部の演奏は続くため、解除時に再生位置や音の減衰が先頭へ戻りません。ソロは試聴専用、ミュートは保存・書き出しにも反映されます。切り替え時にはごく短いフェードを入れています。試聴音量は固定倍率で、過大なピークを抑えるリミッターを通します。WAV書き出しの音声にはこの試聴用処理を加えません。

ブラウザとローカルサーバーが必要です。PCの負荷やバックグラウンドタブの制限で音切れが出る場合は、演奏する画面を前面にしてください。音符・音色などの編集、取り消し、MCPや別画面からのデータ更新では再生が停止します。これらの演奏中の差し替えは未対応です。

WAV・VGM・MGS等の書き出し方式は変わりません。複合音色の短い試聴も従来の方式です。

## 複合音色（実験プリセット）

音符のあるOPLL旋律トラックを選び、音色欄の「複合音色…」を開きます。「二重ベース」は元トラックをAcoustic bass（14）にし、空きOPLL旋律トラックへ同じ音程・タイミングのSynthesizer（10）を追加します。初期音量差は5段階です。追加音が音量1未満になる音符はコピーしません。

追加先と音量差を選び「8秒試聴」で、元パートの最初の音から全体のバランスを確認できます。試聴では楽曲を保存・変更しません。「適用」は1回のUndoで取り消せます。空きがない場合、既存ノートやリズムチャンネルを上書きしません。

これは適用時のノートコピーです。適用後の編集は各パート独立で、自動同期はしません。音量差は実験用の調整値で、特定のゲームの完全再現プリセットではありません。

## OPLL音符ごとの音色・奏法

OPLL旋律の音符を選ぶと、その音だけの音色、デチューン（cent）、ビブラートの深さ・速度（0.1Hz単位）・開始遅延、ポルタメント開始音（MIDI）と時間を指定できます。深さ／移動時間0は無効です。ビブラートは開始後100msで深さが増します。ポルタメントは指定音から対象音へ移動する方式で、ノート間のレガート接続ではありません。

音程更新は50/60Hzの音源レジスタへ反映され、WAV/VGM/レジスタ出力と共通です。ノート別音色または奏法を使用する曲のMGS出力は未対応として停止します。JSONの音符には instrument、detuneCents、vibratoDepth、vibratoRate、vibratoDelayMs、portamentoFrom、portamentoMs を使用します。OPLL旋律以外の指定はエラーになります。


## トラック編集・ドラッグ試聴（v0.8.0）

「トラック編集…」から、同じ音源の別トラックへのコピー、または現在のトラックの一括移動・音量調整を行えます。全体か、開始／終了tickによる範囲を指定します。範囲は音符の開始位置で判定し、終了tickは含みません。ロールの空白をShift＋ドラッグすると、表示小節内の範囲を指定できます。複数小節にまたがる場合はダイアログの数値を指定してください。

時間の移動は＋で後ろ、−で前。96 tickが4分音符、24 tickが16分音符です。「エコー設定」は24 tick遅延・音量値50%を設定します。音量倍率は1〜15の整数値に適用するため、聴感上の音圧比とは異なります。移調は半音単位で、ポルタメントの開始音も移調します。

コピー先の音符は上書きしません。重なり・曲の範囲外・音源固有の制約がある場合は適用せず通知します。終端に余裕がない場合は先に曲の小節数を増やしてください。「音色設定もコピー」は空トラックのみ。SCC 4 / 5の共有波形が変わるコピーは拒否し、もう一方の音色を勝手に変えません。各適用はCtrl+Zで取り消せます。

「ドラッグ試聴」を有効にすると、音符をつかんだときと音程が変わったときに、そのトラックの音色で短く試聴できます。同じ音程での横移動と音長変更では繰り返し発音しません。ミュートされたトラックでも選択した音を試聴できます。試聴は保存されず、音程確認のためビブラート・ポルタメントを付けずに鳴らします。高速な移動中は古い未完了の試聴を破棄し、最新の音程を優先します。
