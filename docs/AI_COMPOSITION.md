# AI composition contract

Read `get_song` before modifying editor state. `get_composition_guide` returns this guide
and the schema. No built-in language model or cloud API is required by the editor.
An MCP-capable external AI composes notes and invokes these tools; the bundled demo is
hand-authored algorithmically and is not presented as generated by an AI.

1. Read the song and revision. Preserve unrelated tracks and user edits.
2. Compose using `start`, `duration` (integer 96 PPQ ticks), MIDI `pitch` (24–95),
   `velocity` (1–15), and unique string `id`. Four quarter notes = 384 ticks per bar.
3. Each hardware channel is monophonic. Allocate chords to separate channels. No overlapping
   notes within one track. Every note must end inside `bars * 384`.
4. Use `validate_song` to catch timing and hardware constraints before `set_song`.
5. Use `set_track_notes` to replace just one track, or `set_song` for atomic whole-song edits.
   Include the exact revision previously read. On conflict, reread and merge; do not blindly retry.
6. Use `export_song` with format `bundle` for a game handoff. Filenames are simple basenames,
   without extensions. Exports stay in outputs and existing files are never overwritten.

Track IDs from new_song: psg1–psg3, opll1–opll9, scc1–scc5. Channel is zero-based.
PSG square tones only. OPLL instrument 0 uses song.opllPatch (eight bytes shared globally),
1–15 select native YM2413 ROM presets. SCC wave is 32 signed integers -128..127; scc4 and
scc5 MUST have identical waves. A track's instrument/wave is fixed for the entire song.
Muted tracks remain editable but are omitted from exported playback.

BPM 40–300, 1–64 bars, total length at most five minutes. Register writes are rounded to the
nearest 50/60 Hz frame. Notes whose on/off collapse to one frame are rejected, not silently
lengthened. The editor uses a constant tempo and 4/4. Loop start is an absolute source tick.
Loop state restoration retriggers sustained FM notes; put loop boundaries at note boundaries.

MML is a strict subset of MGSC 1.11, not a generic parser for every dialect. Supported:
numeric/hex track labels 1–h (PSG 1–3, SCC 4–8, FM 9–h), #opll_mode 0, #tempo,
single-line #title, c–b, r, +/#/-, o, >/<, l, v and relative volume, q1–8,
dotted lengths, % raw lengths (MGSC PPQ 48, doubled into this project's PPQ 96),
^ length ties, [count ...] or [...]count finite repeats, @0–14 FM ROM selection
(mapped to native instrument 1–15), and @sN={64 hex digits} SCC waves with @N selection.
Default volume follows MGSC (v0), so include v explicitly. Only an initial constant t is
accepted. No macros, slurs, LFO, envelopes, rhythm mode, raw register commands, infinite
loops, intermediate instrument changes or alternate endings. Unsupported syntax fails
atomically. JSON is the lossless exchange format; MML text export is not implemented.

`export_song` format `mgs` exports the editor song directly as MGSDRV v3 data using
frame-duration commands (MGS303). Supports all 17 channels, the shared custom OPLL
patch, SCC waves, mute and nonzero loop starts. Requires 60 Hz and at most 16 KiB
of binary data; unsupported/oversize songs fail explicitly without truncation.
MSX playback needs MGSDRV and a compatible player, supplied separately. Driver
tuning and hardware mix levels can differ from the editor. See MGSDRV_EXPORT.md.
