# 試聴しながらAIと編曲する — シシリエンヌ制作例

MCPは、AIがエディタの曲を読み取り、音符を変更し、検証・保存する窓口です。
この例ではASTRAが操作し、人間がブラウザーの再生を聴いて音色やバランスを調整しました。
AIが一度の指示で完成させた例ではなく、対話と試聴を重ねた実例です。

接続設定は [MCP_SETUP.md](../MCP_SETUP.md)、完成データと出典は
[シシリエンヌ・Cantabile](../samples/sicilienne-cantabile/README.md) を参照してください。

## 実際の流れ

| 人間の依頼・判断 | AIによる編集 | MCPでの操作 |
|---|---|---|
| 公開できる楽譜を使ってサンプルにしたい | 原曲と入力資料の権利・出典を確認し、CC0 MusicXML由来の音符を使用 | MCP外で資料を確認し、`get_composition_guide` で音源制約を読む |
| FMを中心に、PSGは控えめ、SCCはフルートの補助 | 主旋律と伴奏を再配分。原譜の旋律300音・伴奏1070音を保持 | `get_song` → `export_song`で退避 → `validate_song` → `set_song` |
| 主旋律を少し下げたい | 主旋律のvelocityだけを1段階下げる（OPLLで約3dB） | `get_song`で最新revisionを取得して、検証後に`set_song` |
| 主旋律にエコーを追加したい | 空けたFM1声へ同音色でコピー。開始+24tick、velocity−2（約−6dB） | パート再配分とエコー追加を一括検証して`set_song` |
| この演奏をサンプルとMP4にしたい | 確定版を保存し、MGS/WAV/VGMと全曲動画を作成 | `export_song`。画面収録とMP4結合はMCP外の作業 |

各変更後、人間がツールの再生ボタンで試聴します。MCPには再生・録画ツールはありません。
ブラウザーへの反映は自動ですが、反映時には再生が止まります。

## 試せる依頼文

> 現在の曲をJSONに退避してください。主旋律トラックを確認し、音高・開始・長さを変えずに
> 音量を1段階下げてください。他のパートは変更せず、検証後にエディタへ反映してください。

> 主旋律に同じFM音色のエコーを追加してください。音量は約半分、開始を24tick遅らせます。
> 使用中のトラックを上書きせず、必要な伴奏の再配分を説明してください。
> 単音制約と曲末のはみ出しを検証し、完成版を別名で保存してください。

完成サンプルにはすでにエコーがあります。試すときはその存在をAIに確認させ、二重に追加しないでください。

## 音源に合わせた判断

- OPLLの音量は線形ではありません。「50%」はvelocityの数値を半分にする意味ではなく、
  この例では2段階下げて約6dB減衰させています。聴感上の大きさが厳密に半分になるわけではありません。
- この曲はBPM 50、PPQ 96。24tickは300msです。原譜の6/8とエディタの4/4表示は異なり、
  ここでいう16分音符はエディタ上の長さです。
- OPLL9声が埋まっていたため、エコー用に1声を空け、伴奏を残りのFMとPSGへ再配分しました。
  リズムモードは使っていません。
- 小さい音量でも、PSGの高音やSCCの倍音は目立つことがあります。数値だけでなく実際に試聴します。
- FMの遅いアタックでは短音が目立たなくなるため、速めすぎると逆に短いノイズが出る場合もあります。この例では速めた設定で瞬間ノイズが発生したため、穏やかな設定へ戻しました。

## 更新・保存の約束

`get_song` が返すrevisionを、変更時の `set_song` に渡します。
競合が返った場合は最新状態を読み直し、他の編集を確認してから変更を作り直してください。
古い曲を新しいrevisionで機械的に上書きしてはいけません。

`export_song` は既存ファイルを上書きしません。タイムスタンプなどを含む新しい名前を指定します。
確定版のJSONは編集可能な原本として保存し、WAV・MGS・MP4とは別に保管してください。

今回のソース再生成とMCP呼び出しは、サンプル内の `arrange.py` と `mcp_example.py` で確認できます。
同じ入力からのデータ再生成は検証していますが、自然言語の依頼から毎回同じ編曲になる保証はありません。
